# Закрытие связанных задач по отдельности

Форма закрытия загружает основные заявки InControl по точному борту и парку в фоне. Для импортированной записи используется Task.incontrol_task_id. Если привязки нет и основных заявок несколько, пользователь выбирает нужную. Загрузка и выбор не меняют этапы и не запрашивают подпись.

Для каждой связанной задачи показаны её номер, вид работ и описание, поле выполненных работ/причины отклонения и кнопки «Выполнено»/«Отклонено». Решения проверяются сервером по полному актуальному списку связей. Запрещены пропущенные, чужие и повторные номера, изменение уже завершённых задач на противоположный результат. Тексты услуг передаются только соответствующим задачам. Для сервисных дочерних без поля услуг меняется только этап, чек-листы не переписываются.

Результат основной заявки выбирает приёмщик внизу формы: «Выполнено» или «Отклонено». При выполнении используются отдельные решения дочерних и обычные две подписи. При отклонении карточки скрываются, остаётся одна общая причина: связанные отклоняются только сменой этапа, причина записывается в основную заявку, подписывается заявка без акта. Результат основной больше не вычисляется из дочерних решений. Перед изменениями повторно проверяются борт, парк, связи, личность, разрешения и состав решений. Выбранная основная привязывается к локальной записи перед выполнением; уникальность процесса удалённой заявки проверяется БД до HTTP-изменений.

В Сетранс сохраняется сводка отдельными строками. Полная информация о решениях и черновике хранится в зашифрованном payload существующей таблицы incontrol_rejection_run, поэтому новый SQL не нужен. После начала изменений черновик нельзя подменить; обновление страницы восстанавливает сохранённые данные, повтор учитывает завершённые шаги.

## Установка

Распаковать архив обновления в корень проекта с заменой файлов и перезапустить приложение. В архив входят app.py, incontrol_rejection.py, incontrol_fulfillment.py, incontrol_rejection_jobs.py, incontrol_child_plan.py, incontrol_completion.py, templates/complete_task.html, static/js/incontrol-inline.js, static/js/incontrol-plan.js и эта инструкция. Остальные модули личных аккаунтов, сеанса и фоновых проверок остаются необходимыми зависимостями установленной ранее интеграции. Не менять SECRET_KEY: им защищены сохранённые настройки и процессы.

## Автоматическая загрузка без кнопки

Связанные задачи загружаются при открытии формы закрытия. Для привязанной или единственной основной заявки дополнительных действий нет; если основных несколько, после выбора из списка чтение связанных начинается сразу, без кнопки загрузки. Список и этапы читаются из InControl заново, импортированный текст не используется как актуальный снимок закрытия.

Если в InControl открытых заявок нет, показывается обычное поле выполненных работ и нижний выбор результата основной заявки с кнопкой сохранения. Перед сохранением отсутствие проверяется ещё раз. Проверены 14 целевых тестов, включая оба способа локального закрытия без InControl. Для этого продолжения обновить static/js/incontrol-plan.js и templates/complete_task.html; SQL не нужен.

## Общая причина отклонения основной заявки

Выбор результата основной независим от результатов дочерних задач. При переключении на отклонение вводится одна обязательная причина; отдельные решения в этом режиме не отправляются. При возвращении к выполнению тексты и выбранные результаты карточек сохраняются в форме. Сервер сверяет общий результат с действием и сохраняет его в защищённом черновике; после начала удалённых изменений переключить результат нельзя. Перед общим отклонением перечитываются связи и проверяется, что состав не изменился. Если дочерняя задача уже выполнена, автоматическое общее отклонение требует ручной сверки.

Проверено 138 тестов и полный цикл общего отклонения на изолированном стенде. Реальные заявки в этом изменении не закрывались. Обновить incontrol_rejection_jobs.py, incontrol_child_plan.py, templates/complete_task.html, static/js/incontrol-plan.js и перезапустить приложение. SQL не нужен.

## Единственная связанная задача

Если связанная задача одна, её отдельные кнопки результата скрываются. Для открытой задачи результат берётся из нижнего выбора основной заявки: при выполнении отправляются работы единственной задачи, при отклонении используется одна общая причина. Уже завершённые в InControl задачи сохраняют фактический этап. Если задач две и более, отдельные переключатели остаются. Нижний выбор оформлен компактной парой зелёной/красной кнопок в том же стиле, что и карточки задач. Обновить templates/complete_task.html и static/js/incontrol-plan.js; SQL не нужен.

## Сначала выбор результата, затем форма

Новая форма первоначально показывает только номер борта и кнопки «Выполнено»/«Отклонено», без выбранного по умолчанию результата. При выполнении загружается актуальный список связанных задач: под заголовком «Описание заявки» для каждой задачи показано её название, справа — индивидуальный результат (только если задач не меньше двух), ниже — поле работ. Дублирующий объединённый текст скрыт. При отклонении показана общая причина. Нижняя кнопка в обоих режимах называется «Завершить». Переключение результата сохраняет введённый черновик. Уже начатые процессы продолжаются с ранее выбранным результатом. Сходный начальный выбор применяется и к локальным задачам в парках без InControl.

Обновить templates/complete_task.html, static/js/incontrol-plan.js и static/js/incontrol-inline.js, затем перезапустить приложение. SQL не нужен. Проверены 71 целевой тест и сценарии формы в браузере на изолированном стенде.
